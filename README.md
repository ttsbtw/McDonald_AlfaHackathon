# Умный кредитный кабинет предпринимателя

Проект команды **МакДоналд** для хакатона **«Альфа-Будущее 2026»**.

Цифровой кредитный кабинет для малого и микробизнеса, объединяющий подачу заявки предпринимателем и её рассмотрение сотрудником банка в одном веб-приложении.

## О проекте

Предпринимателю важно понимать, какой продукт выбрать, какие сведения предоставить и что происходит с заявкой после отправки. Сотруднику банка нужны данные о бизнесе, результаты проверок и основания для принятия решения.

Наш проект связывает эти задачи в единый процесс с сохранением данных, последовательными состояниями заявки и объяснимой оценкой кредитного риска.

## Основной сценарий

1. **Выбор продукта.** Предприниматель указывает цель, сумму и срок финансирования.

2. **Подготовка заявки.** Заполняет сведения о компании и финансовых показателях бизнеса.

3. **Автоматические проверки.** Система проверяет данные и получает информацию из локальных симуляторов внешних источников.

4. **Скоринговая оценка.** Рассчитывается балл и формируется предварительная рекомендация с объяснением.

5. **Рассмотрение сотрудником.** Сотрудник банка принимает решение или запрашивает уточнения.

6. **Получение результата.** Предприниматель видит статус, решение и дальнейшие действия в кабинете.

## Архитектурный подход

Приложение строится как модульный монолит: веб-интерфейс взаимодействует с backend API, а backend управляет заявками, хранением данных, проверками и вызовом скоринга.

Модуль скоринга отделён от API и базы данных, чтобы его можно было независимо тестировать и развивать.

## Принципы решения

- **Прозрачность:** клиент понимает состояние заявки и необходимые действия.

- **Объяснимость:** оценка сопровождается факторами и причинами рекомендации.

- **Разделение ответственности:** скоринг оценивает риск, итоговое решение принимает сотрудник.

- **Автономность:** основной сценарий не зависит от платных API и корпоративных систем банка.

- **Воспроизводимость:** внешние интеграции моделируются локально, демонстрационные данные синтетические.

## Границы прототипа

Проект предназначен ТОЛЬКО для демонстрации кредитного процесса. Условия продуктов и правила оценки являются демонстрационными и не представляют реальную кредитную политику Альфа-Банка.

## Локальный запуск

Для запуска всего приложения нужны Docker Desktop (или Docker Engine) и Docker Compose v2. Команды выполняются из корня репозитория.

Если файла `.env` ещё нет, создайте его из примера:

```sh
test -f .env || cp .env.example .env
```

Откройте `.env` и задайте непустой `JWT_SECRET` (можно сгенерировать командой `python3 -c "import secrets; print(secrets.token_hex(32))"`, скопировать и вставить) и пароль `POSTGRES_PASSWORD`. Если тесты проходят на Windows без возможности использовать скриптов Py, то можно открыть .env в блокноте и заменить пустое значение JWT_SECRET= на длинную случайную строку, например 64 символа из букв и цифр. Для пароля базы используйте латинские буквы, цифры, `_` и `-`. В примере включено создание демонстрационных учётных записей (`SEED_DEMO=true`); их логины и пароли описаны в [инструкции backend](backend/README.md).

Соберите образы и запустите сервисы:

```sh
docker compose up --build -d
docker compose ps
```

После того как сервисы запустятся, откройте:

- Веб-приложение: <http://localhost:5173>
- API и Swagger: <http://localhost:8000/docs>
- Проверка готовности backend и базы данных: <http://localhost:8000/ready>

Остановить приложение, сохранив данные базы:

```sh
docker compose down
```

## ИИ-анализ скоринга (по желанию)

Кабинет сотрудника может запросить локальное пояснение к результатам одной заявки. Проверенный ответ сохраняется и показывается после повторного открытия карточки; при запросе уточнений или изменении анкеты он сбрасывается. Основной сценарий работает без Ollama; ИИ не меняет оценку, обязательные проверки, статус или итоговое решение.

Перед клонированием установите и включите Git LFS (`brew install git-lfs && git lfs install` на macOS). Уже клонированный репозиторий можно заполнить командами `git lfs install && git lfs pull`. Затем выполните инструкцию импорта весов и запуска в [docs/ollama-ai-analysis.md](docs/ollama-ai-analysis.md). Документ включает контрольную сумму модели, настройки Docker → Ollama и проверку четырёх синтетических сценариев.

Удалить данные из базы не перезапуская контейнер можно этой командой:

```sh
docker compose exec -T db psql -U credit_cabinet -d credit_cabinet -c 'TRUNCATE TABLE applications RESTART IDENTITY CASCADE;'
```

Данные PostgreSQL хранятся в Docker-томе и сохраняются при обычной остановке. Не используйте `docker compose down -v`, если хотите сохранить их. После получения новых изменений из GitHub пересоберите и запустите сервисы командой `docker compose up --build -d`.
