# Умный кредитный кабинет предпринимателя

Проект команды **МакДоналд** для хакатона **«Альфа-Будущее 2026»** — веб-приложение для подачи и рассмотрения заявок малого и микробизнеса.

## Полная установка и запуск

Ниже приведён полный путь установки: веб-приложение, база данных и локальный ИИ-анализ скоринга. Frontend, backend и PostgreSQL запускаются в Docker Compose. Ollama с моделью работает отдельно на компьютере.

### Что понадобится

- Docker Desktop на macOS или Windows либо Docker Engine на Linux;
- Docker Compose v2 (команда `docker compose`);
- Git;
- Git LFS для загрузки весов модели из репозитория;
- Ollama для локального запуска Qwen;
- Python 3 для скрипта сборки файла модели;

Проверьте Docker и Compose:

```sh
docker --version
docker compose version
```

### 1. Установите Git LFS и получите проект вместе с весами

Установите Git LFS по инструкции для своей операционной системы на [git-lfs.com](https://git-lfs.com/), затем включите его:

```sh
git lfs install
```

После этого клонируйте репозиторий и перейдите в его папку:

```sh
git clone https://github.com/ttsbtw/McDonald_AlfaHackathon.git
cd McDonald_AlfaHackathon
git lfs pull
```

Если репозиторий уже склонирован, выполните `git lfs install` и `git lfs pull` из его корня. Git LFS скачает три части Qwen3-4B-Instruct-2507 Q4_K_M; общий размер модели — около 2,5 ГБ.

### 2. Установите Ollama и соберите модель

Скачайте Ollama с [официальной страницы](https://ollama.com/download)
ИЛИ
воспользуйтесь этими командами:

Для Linux/MacOS:
```sh
curl -fsSL https://ollama.com/install.sh | sh
```
Для Windows:
```sh
irm https://ollama.com/install.ps1 | iex
```
 и запустите приложение или службу Ollama. Оставьте её запущенной, пока используете ИИ-анализ.

В терминале из корня репозитория восстановите единый файл модели и импортируйте его в Ollama:

macOS / Linux:

```sh
python3 scripts/prepare_qwen3_model.py
```

Windows PowerShell:

```powershell
py scripts/prepare_qwen3_model.py
```

Скрипт объединит LFS-части во временном каталоге, проверит размер и SHA-256 по манифесту и создаст локальный тег модели. Проверьте, что Ollama его видит:

```sh
ollama list
```

В списке должна быть модель `qwen3:4b-instruct-2507-q4_K_M`. Если скрипт сообщает, что отсутствуют части или найдены LFS-указатели, повторите `git lfs pull`.

### 3. Создайте и настройте `.env`

Откройте терминал в корне репозитория. Создайте файл настроек копированием примера (.env.example). Если `.env` уже существует, не перезаписывайте его.

macOS / Linux:

```sh
test -f .env || cp .env.example .env
```

Windows PowerShell:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Откройте `.env` в текстовом редакторе и задайте `JWT_SECRET` — случайную строку не короче 32 символов. Сгенерировать её можно так:

```sh
python3 -c "import secrets; print(secrets.token_hex(32))"
```

На Windows выполните команду через `py -c`.

Скопируйте строку после `JWT_SECRET=`. Это секрет подписи токенов входа.

Убедитесь, что настройки Ollama в `.env` указаны так:

```dotenv
OLLAMA_BASE_URL=http://host.docker.internal:11434
OLLAMA_MODEL=qwen3:4b-instruct-2507-q4_K_M
OLLAMA_TIMEOUT_SECONDS=120
```

На macOS и Windows с Docker Desktop адрес `host.docker.internal` направляет backend-контейнер к Ollama на компьютере. На Linux укажите в `OLLAMA_BASE_URL` адрес Ollama, доступный из Docker-контейнера; `localhost` внутри backend-контейнера указывает на сам контейнер, а не на компьютер.

В `.env.example` уже заданы пароль PostgreSQL и настройки демонстрационных аккаунтов. Их можно оставить для локального прототипа. Если меняете `POSTGRES_PASSWORD`, используйте латинские буквы, цифры, `_` и `-`. Демонстрационные пароли предназначены только для локального запуска.

### 4. Соберите и запустите приложение

Из корня репозитория выполните:

```sh
docker compose up --build -d
```

При первом запуске Docker скачает образы и соберёт frontend и backend. Compose запустит PostgreSQL, дождётся готовности базы, применит миграции и поднимет API и веб-интерфейс. Первый запуск может занять несколько минут.

Проверить состояние сервисов:

```sh
docker compose ps
```

### 5. Войдите и проверьте функции

| Что открыть | Адрес |
| --- | --- |
| Кабинет клиента и сотрудника | <http://localhost:5173> |
| Swagger API | <http://localhost:8000/docs> |
| Проверка готовности API и базы | <http://localhost:8000/ready> |

При `SEED_DEMO=true` создаются следующие демонстрационные учётные записи:

| Роль | Логин | Пароль по умолчанию |
| --- | --- | --- |
| Клиент первой компании | `client1` | `Client-one-demo-2026!` |
| Клиент второй компании | `client2` | `Client-two-demo-2026!` |
| Сотрудник банка | `employee` | `Employee-demo-2026!` |

Для проверки создайте и отправьте заявку под `client1` или `client2`, затем войдите как `employee`, откройте заявку из очереди и запустите «Проанализировать скоринг с помощью ИИ». Ответ модели отображается в карточке заявки. ИИ поясняет уже рассчитанные результаты и не меняет баллы, обязательные проверки, статус или решение сотрудника.

Если стандартный порт занят, задайте свободный `FRONTEND_PORT` или `BACKEND_PORT` в `.env` и пересоздайте сервисы. Если база уже была создана, изменение пароля пользователя в `.env` не изменит сохранённый пароль; подробнее — в [инструкции backend](backend/README.md#демонстрационные-учётные-записи).

**Если вы хотите запустить только кредитный кабинет, шаги с Ollama и Git LFS можно пропустить.** Без модели останутся доступны подача заявок, скоринг, проверки и рассмотрение сотрудником; кнопка ИИ-анализа работать не будет. Для этого варианта достаточно настроить `.env` без изменения параметров Ollama и выполнить шаги запуска Docker Compose.

## Остановка, повторный запуск и данные

Остановить контейнеры, сохранив заявки и пользователей:

```sh
docker compose down
```

Запустить ранее собранные образы снова:

```sh
docker compose up -d
```

После обновления кода стоит пересобрать образы заново: `docker compose up --build -d`.

PostgreSQL хранит данные в Docker-томе `postgres_data`. **Не запускайте `docker compose down -v`, если хотите сохранить данные**: флаг `-v` удаляет том с базой. Для полной очистки демонстрационных заявок обратитесь к [инструкции backend](backend/README.md).

### Если приложение или ИИ-анализ не запускаются

- **Docker не отвечает.** Запустите Docker Desktop или Docker Engine, затем повторите команду.
- **Ошибка `JWT_SECRET`.** Проверьте, что `.env` создан в корне проекта и секрет содержит не менее 32 символов.
- **Контейнер `backend` не становится `healthy`.** Посмотрите `docker compose logs backend` и `docker compose logs db`; проверьте настройки PostgreSQL в `.env`.
- **Порт уже занят.** Измените `FRONTEND_PORT` и/или `BACKEND_PORT` в `.env` и пересоздайте сервисы.
- **Модель не найдена.** Проверьте `ollama list`, затем при необходимости выполните `git lfs pull` и повторите `python3 scripts/prepare_qwen3_model.py` (в Windows — `py scripts/prepare_qwen3_model.py`).
- **Backend не соединяется с Ollama.** Убедитесь, что Ollama запущена и `OLLAMA_BASE_URL` указывает на адрес, доступный из контейнера. Подробные причины ошибок перечислены в [инструкции Ollama](ai-docs/ollama-ai-analysis.md#ошибки).

Подробная документация по API, демонстрационным данным и обработке заявок находится в [README backend](backend/README.md). Полное описание модели, её весов и проверочного набора — в [инструкции локального ИИ-анализа](ai-docs/ollama-ai-analysis.md).

## О проекте

Предприниматель подаёт заявку и следит за её статусом; сотрудник банка видит сведения о бизнесе, скоринг и результаты проверок. Демонстрационный конвейер сохраняет версии заявок и оценок, объясняет предварительную рекомендацию и оставляет итоговое решение сотруднику.

### Основной сценарий

1. Предприниматель выбирает продукт, указывает цель, сумму и срок финансирования.
2. Заполняет сведения о компании и финансовых показателях.
3. Система выполняет локальные симулированные проверки.
4. Скоринг рассчитывает балл и предварительную рекомендацию.
5. Сотрудник рассматривает заявку, может запросить сведения, одобрить или отказать с указанием причины.
6. Клиент видит статус заявки и дальнейшие действия.

### Технологии

| Направление | Технологии |
| --- | --- |
| Frontend | React, Vite, JavaScript |
| Backend | Python, FastAPI |
| База данных | PostgreSQL |
| Инфраструктура | Docker Compose |
| Скоринг | Python, балльная модель и бизнес-правила |
| ИИ-пояснение | Ollama локально |

Приложение построено как модульный монолит: frontend взаимодействует с backend API, backend управляет заявками, хранением данных, проверками и вызовом скоринга. Модуль скоринга отделён от API и базы данных.

## Ограничения прототипа

Проект предназначен **только для демонстрации** кредитного процесса. Условия продуктов и правила оценки являются демонстрационными и не представляют реальную кредитную политику Альфа-Банка. Проверки БКИ и Compliance используют синтетические данные.
