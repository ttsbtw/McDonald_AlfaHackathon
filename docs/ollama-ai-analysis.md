# Локальный ИИ-анализ скоринга

ИИ-анализ запускается сотрудником из карточки конкретной заявки. Backend берёт только её анкету и сохранённый результат скоринга, БКИ, Compliance и underwriting. История компании и другие заявки не добавляются в контекст. Каждый вызов — отдельный запрос с двумя сообщениями, без сохранённого состояния диалога.

Результат поясняет уже рассчитанные данные. Он не меняет балл, риск, результаты обязательных проверок, статус или решение. Backend проверяет JSON по Pydantic-схеме и сверяет все ссылки на факты с переданным списком. При стоп-факторе или underwriting `REVIEW`/`REJECT` сервер сам возвращает причину блокировки и заменяет рекомендацию на обязательную ручную проверку. Отсутствующие обязательные поля также показываются как отдельные предупреждения, сформированные из результата скоринга. Если текст модели содержит неподтверждённое число, вывод об одобрении или неподкреплённую причину, он заменяется серверным пересказом проверенных фактов; интерфейс сообщает об этом сотруднику. Невалидный JSON или несоответствие схеме приводит к понятной ошибке и кнопке повтора.

В audit log сохраняются ID заявки и оценки, ID анализа, тег модели, версия промпта и время. Текст ответа и внутренние рассуждения модели не сохраняются.

## Установка на macOS

1. Установите Ollama с [официальной страницы загрузки](https://ollama.com/download) и запустите приложение Ollama.
2. Перед клонированием репозитория установите Git LFS и включите его фильтры. На macOS:

   ```sh
   brew install git-lfs
   git lfs install
   ```

   Если репозиторий уже клонирован без LFS, выполните в его корне `git lfs install && git lfs pull`.
3. Убедитесь, что LFS получил все части, затем восстановите тег Ollama:

   ```sh
   python3 scripts/prepare_qwen3_model.py
   ollama list
   ```

   Скрипт склеит три части во временном каталоге, проверит SHA-256 и импортирует Qwen3-4B-Instruct-2507 Q4_K_M под тегом `qwen3:4b-instruct-2507-q4_K_M`.
4. Создайте или обновите `.env` в корне репозитория:

   ```dotenv
   OLLAMA_BASE_URL=http://host.docker.internal:11434
   OLLAMA_MODEL=qwen3:4b-instruct-2507-q4_K_M
   OLLAMA_TIMEOUT_SECONDS=120
   ```

   `.env` уже исключён из Git. Адрес `host.docker.internal` позволяет backend-контейнеру обращаться к Ollama на Mac.
5. Пересоберите и запустите приложение:

   ```sh
   docker compose up --build -d
   ```

6. Откройте карточку заявки сотрудника и нажмите **«Проанализировать скоринг с помощью ИИ»**. Анализ доступен только для заявки с актуальной сохранённой оценкой.

Для Linux или другой схемы запуска укажите `OLLAMA_BASE_URL` как сетевой адрес Ollama, достижимый из backend-контейнера. Не используйте `localhost` внутри контейнера, если Ollama работает на хосте.

## Модель в Git LFS

Вес GGUF включён в репозиторий как три Git LFS-объекта (`models/qwen3-4b-instruct-2507-q4_K_M/model.gguf.part-*`), размер каждого не превышает 850 MiB. GitHub блокирует одиночные обычные Git-файлы свыше 100 MiB. LFS хранит в Git указатели, а сами бинарные объекты — в хранилище LFS; при клонировании нужен установленный Git LFS и достаточный лимит хранилища/скачиваний аккаунта. На тарифах GitHub Free и Pro включено по 10 GiB хранилища и трафика LFS; один полный клон этой модели расходует около 2,5 GB трафика. Скрипт сборки проверяет точный размер и SHA-256. Исходные лицензионные сведения находятся рядом с частями модели.

## Ошибки

| Сообщение/код API | Что проверить |
| --- | --- |
| `OLLAMA_UNAVAILABLE` | Убедитесь, что приложение Ollama запущено, `ollama list` отвечает, а `OLLAMA_BASE_URL` доступен из backend-контейнера. |
| `OLLAMA_MODEL_MISSING` | Выполните `python3 scripts/prepare_qwen3_model.py` из корня проекта и проверьте точный тег через `ollama list`. |
| `AI_ANALYSIS_INVALID_RESPONSE` | Повторите анализ. Ошибка означает, что ответ не прошёл JSON-схему, размерный лимит или проверку ссылок на факты. Невалидный текст не показывается как результат. |
| Заявка требует актуальной оценки | Клиент должен повторно отправить актуальную редакцию; анализ устаревшей оценки не выполняется. |

Обычная работа конвейера не зависит от Ollama: её недоступность влияет только на эту дополнительную кнопку.

## Проверки и пробная оценка

Офлайн-проверки покрывают корректный JSON, невалидный/неполный JSON, ссылки на несуществующие факты, недоступную Ollama, отсутствие модели и обязательную Compliance-блокировку при высоком скоринге. API-проверка подтверждает доступ только для сотрудника, журналирование метаданных и неизменность статуса и балла.

После запуска локальной модели выполните набор из четырёх сценариев оценки из `backend/scripts/evaluate_ai_analysis.py`: обычная заявка, высокий риск, обязательное ограничение и неполные данные. Скрипт проверяет, что ссылки принадлежат исходным фактам, блокировка не снимается, а неполные поля предупреждаются. Первая пробная оценка для текущего тега записана в [отчёте](ai-analysis-evaluation-2026-10-24.md) и [JSON-выводе](ai-analysis-evaluation-2026-10-24.json). Три из четырёх ответов потребовали проверенного серверного пересказа; это явно отображается сотруднику. Внутренние рассуждения не записываются.
